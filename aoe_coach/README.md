# Разбор эпизодов AoE — первая версия

Работает по существующему roster-логу JSONL или ZIP с одним JSONL. Повторно запускать игру не нужно. Python 3.9+, без сторонних библиотек. HTML от старого overview в качестве входа не подходит.

Распакуйте aoe_coach рядом с .venv в папке aoe_trace.

```powershell
.venv\Scripts\python.exe .\aoe_coach\analyze.py 'C:\путь\capture.zip' --player 1 --opponents 2 --out '.\coach.html'
```

Замените путь и номера игроков. Для нескольких соперников: `--opponents 2 3`. Союзников не указывайте: отношения между игроками не выводятся автоматически. Без --opponents сравнения с другими игроками не выполняются. Без --player формируются индивидуальные эпизоды для всех игроков.

Откройте coach.html двойным щелчком. Рядом создаётся coach.json с фактами, исходными числами и диагностикой. Оба выходных имени должны быть свободны.

## Что показывает

- Сокращение жителей на 3 и более либо сухопутных боевых/кораблей на 5 и более за окно.
- Рост одного запаса минимум на 500 до 1000 и более при отсутствии чистого роста общей боевой численности.
- Ухудшение разницы численности с явно указанным соперником минимум на 10; суша и корабли рассматриваются отдельно.
- Для каждого сигнала: интервал игрового времени, наблюдаемый факт, что проверить в повторе и условный вывод для следующей игры. Есть таблица показателей всех записанных игроков до/после и фильтр игрока.

По умолчанию окно 60 игровых секунд. `--window 120` изменяет его. Однотипные сигналы для того же игрока/соперника подавляются на длину окна, поэтому это подборка эпизодов, а не полный список срабатываний. При дискретных снимках фактическое окно может быть немного длиннее заданного; в карточке показаны точные границы.

Разрыв между снимками более 5 секунд или сброс времени начинают новый участок: через него сравнения не строятся. Порог меняется через `--max-gap 10`. Пропущенные балансы не заменяются нулями; через такой пропуск сигналы накопления не строятся. Незавершённая доставка и лимиты отражаются в отчёте. Повреждённый JSON останавливает обработку с номером строки.

## Как использовать для тренировки

1. Выберите своего игрока и один-два важных эпизода.
2. Откройте повтор за минуту до указанного интервала.
3. Проверьте предполагаемые причины с учётом того, что было видно вам тогда.
4. Если причина подтверждается, выберите одно действие для тренировки в следующей партии.
5. Проверьте, повторяется ли проблема в других партиях.

Пороги — эвристики поиска, а не нормы оптимальной игры. Запас мог быть запланирован. Новые войска могли погибать сразу, поэтому отсутствие чистого роста не доказывает простой. Сокращение списка не равно смертям: возможны обращения, гарнизоны и неполнота учёта. Численность не равна боевой силе. Нет достоверных очередей, улучшений, видимости и причин исчезновения объектов. Нулевое число сигналов не означает, что ошибок не было. Скрипт не определяет победителя и не устанавливает причин поражения.

Считаются активные объекты состояния 2. Классы совпадают с текущим overview: лучники 0, пехота 6, конница 12/47, осадные 13/35/51/54, корабли 22, жители 4. Поддержка, короли и хозяйственные суда исключены из боевого итога. Неизвестные классы отмечаются в сводке; классификация модифицированных юнитов может потребовать уточнения.

## Размер и проверки

Исходный лог читается последовательно, объекты каждого юнита не копируются в отчёт. В памяти остаются сводки за окно, краткая статистика участков и найденные эпизоды. Размер отчёта зависит от числа эпизодов, а не напрямую от количества полных снимков. Старый HTML размером 1 ГБ не нужен и не исправляется этим инструментом.

Проверено на существующих JSONL/ZIP и синтетических сценариях: сигналы, разрывы/сбросы времени, отсутствующие балансы, совпадение ZIP и JSONL, повреждённые строки.

```powershell
.venv\Scripts\python.exe -m unittest discover -s .\aoe_coach -p 'test_*.py'
```
